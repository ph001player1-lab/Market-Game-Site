# Рыночек Порешает (Market Game) — сайт игры

Статический лендинг бизнес-симулятора Market Game (по-русски — «Рыночек Порешает»).
Обычный HTML: никаких сборок, зависимостей и внешних сервисов.
Домен: **marketgame.club**

Сайт только на английском, переключателя языков нет:

| Страница | Адрес | Файл |
|---|---|---|
| Главная — игра | `marketgame.club` | `index.html` |
| Phuket Business League | `marketgame.club/phuket/` | `phuket/index.html` |
| Политика конфиденциальности | `marketgame.club/privacy.html` | `privacy.html` |

Русские версии главной, политики и пхукетской страницы лежат в архиве
`_archive/` — см. раздел «Архив» ниже. Старые адреса `/en/`, `/en/privacy.html`,
`/vi/`, `/phuket/ru/` и `/phuket/th/` перенаправляют на новые, чтобы уже
разошедшиеся ссылки не вели в пустоту.

## Что где менять

Главное правило: **вёрстка и логика — общие, текст и цифры — в каждой
странице свои.**

| Что меняете | Где |
|---|---|
| Цвета, отступы, размеры, любой внешний вид | `styles.css` — один раз, применится ко всем языкам |
| Формулу рынка, поведение ползунков | `sim.js` — один раз, применится ко всем языкам |
| Любой текст на сайте | в нужной языковой странице, **отдельно в каждой** |
| Ссылка на группу | `t.me/Market_Game_by_Nickbv` в каждой странице |
| Ссылка на личный Telegram | `t.me/nickbv` в каждой странице |
| Число участников, длительность хода | блок `<dl class="specs">` в каждой странице |
| Биография автора | блок `<ul class="regs">` в каждой странице |
| Инструменты игрока | блок `<div class="tools">` в каждой странице |

Текст правится прямо в HTML между тегами — это обычные абзацы,
никакого шаблонизатора нет.

Если правите смысловой текст (например, описание формата), не забудьте
внести ту же правку во все три страницы, иначе версии разойдутся.

### Картинки

Все картинки лежат в корне репозитория. Чтобы заменить картинку,
загрузите новый файл под тем же именем.

**Важно про размеры.** В HTML у каждой картинки проставлены `width` и
`height` — это реальные пиксели файла. Они нужны, чтобы страница не
«прыгала» при загрузке. Если загружаете картинку с другими пропорциями,
поправьте эти два числа в теге `<img>`, иначе под картинку зарезервируется
место неправильной формы.

**Важно про формат.** Держите картинки в JPG. Тот же рендер в PNG весит
в 10–15 раз больше (2,7 МБ против 190 КБ) — на телефоне разница заметная.
Если у вас на руках PNG, сохраните его как JPG с качеством 85–90: на глаз
отличий нет. Ширины больше 1150 пикселей смысла не имеет, шире картинка
на сайте нигде не показывается.

Размеры: `author.jpg` — 560×700, превью `og-en.jpg` и `phuket/og.jpg` — строго 1200×630.

Превью ссылки: `og-en.jpg` — для главной, `phuket/og.jpg` — для страницы
сообщества. Какое брать, указано в строке `og:image` в начале страницы.

## Приём заявок

Кнопки «Записаться на игру» открывают форму. Она собирает имя, телефон и ник
в Telegram, кладёт заявку в Google-таблицу и присылает уведомление в закрытую
группу Telegram.

Сайт — статика на GitHub Pages, а значит **хранить пароли и токены на нём
негде**: всё, что попало в HTML или JavaScript, видно любому посетителю.
Поэтому заявку принимает промежуточный скрипт на стороне Google, а токен бота
лежит в его настройках.

```
Форма на сайте
   │ отправка
   ▼
Google Apps Script
   ├─→ строка в Google-таблице  (это ваша база, выгружается в Excel)
   └─→ сообщение в закрытую группу Telegram
```

### Настройка, один раз минут за пятнадцать

**1. Таблица и скрипт**

1. Создайте новую Google-таблицу — это будет база лидов.
2. `Расширения` → `Apps Script`.
3. Удалите всё из `Code.gs` и вставьте содержимое файла `apps-script/Code.gs`
   из этого репозитория.

**2. Бот**

4. В Telegram найдите `@BotFather`, отправьте `/newbot`, придумайте имя.
   BotFather пришлёт токен вида `1234567890:AAH...` — скопируйте его.

**3. Группа для уведомлений**

5. Создайте закрытую группу, например «Лиды».
6. Добавьте в неё вашего бота и сделайте администратором.
7. Напишите в группе любое сообщение.
8. Откройте в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates`,
   подставив свой токен. Найдите в ответе `"chat":{"id":-100...}` —
   это `chat_id` группы, с минусом. Скопируйте.

> Почему группа, а не личные сообщения: Telegram запрещает боту писать
> человеку, который сам не начал с ним диалог. С группой этой возни нет —
> **нанимаете менеджера, добавляете в группу; увольняете — удаляете.**
> Ни кода, ни настроек трогать не нужно.

**4. Ключи в скрипт**

9. В редакторе Apps Script: `Настройки проекта` (шестерёнка) →
   `Свойства скрипта` → `Добавить свойство`. Добавьте два:

   | Свойство | Значение |
   |---|---|
   | `BOT_TOKEN` | токен от BotFather |
   | `CHAT_ID` | id группы, с минусом |

10. Вернитесь в редактор, выберите функцию `testTelegram` и нажмите
    `Выполнить`. В группу должно прийти тестовое сообщение. Если пришло —
    связка работает.

**5. Публикация**

11. `Развернуть` → `Новое развёртывание` → тип `Веб-приложение`.
12. `Запуск от имени`: **я**. `У кого есть доступ`: **все**.
13. Нажмите `Развернуть`, скопируйте адрес вида
    `https://script.google.com/macros/s/.../exec`.
14. Вставьте этот адрес в поле `endpoint` во всех страницах с формой:
    `index.html` и `phuket/index.html`
    (ищите `window.FORM_CONFIG`).

Готово. Проверьте: отправьте заявку с сайта — строка должна появиться
в таблице, сообщение в группе.

> **Важно после любой правки `Code.gs`:** Apps Script не подхватывает
> изменения сам. Нужно `Развернуть` → `Управление развёртываниями` →
> карандаш → `Версия: новая` → `Развернуть`. Адрес при этом не меняется.

### Если что-то не работает

**Первым делом запустите проверку.** В редакторе Apps Script выберите в
списке функций наверху `checkSetup` и нажмите `Выполнить`. Она пройдёт по
всем шагам и прямо напишет, что сломалось:

```
--- Проверка настройки ---
✓ BOT_TOKEN задан (46 символов)
✓ CHAT_ID задан: -1001234567890
✓ Токен рабочий, бот: @ваш_бот
✓ Сообщение отправлено — проверьте группу
✓ Лист «Лиды» готов, строк с данными: 0
```

Если на каком-то шаге стоит `✗` — там же написано, что делать.

`testLead` — второй помощник: имитирует настоящую заявку, пишет строку
в таблицу и шлёт сообщение. Тестовую строку потом удалите из таблицы.

**Разбор частых случаев:**

| Что видите | В чём дело | Что сделать |
|---|---|---|
| `Не задан BOT_TOKEN` или `CHAT_ID` | свойства не сохранились | Настройки проекта → Свойства скрипта. Имена заглавными, без пробелов. Нажать сохранение |
| `Telegram не принял токен: Unauthorized` | токен неверный | Взять заново у `@BotFather` |
| `chat not found` | неверный `chat_id` | У групп он **отрицательный**, обычно `-100…`. Минус обязателен |
| `bot was kicked` | бота нет в группе | Добавить обратно |
| `have no rights to send a message` | бот не админ | Выдать права администратора |
| Окно Google с запросом доступа | первый запуск | Согласиться и запустить снова |
| Заявка в таблице есть, в Telegram нет | связка с ботом сломана | Запустить `checkSetup` — она покажет причину |
| С сайта форма не отправляется | код не развёрнут | Открыть `/exec` в браузере, см. ниже |

**Проверка развёртывания.** Откройте свой адрес `/exec` в браузере.
Должно вернуться примерно это:

```json
{"status":"ok","service":"marketgame-leads","hasToken":true,"hasChatId":true}
```

- Видите другое или страницу с ошибкой → код не вставлен или не передеплоен
- `"hasToken":false` → не задан `BOT_TOKEN`
- `"hasChatId":false` → не задан `CHAT_ID`

Сам токен наружу не отдаётся, только признак «задан».

**Проверка в обход скрипта.** Чтобы понять, где сломано — в Telegram или
в Apps Script, — откройте в браузере, подставив свои значения:

```
https://api.telegram.org/bot<ТОКЕН>/sendMessage?chat_id=<CHAT_ID>&text=проверка
```

Пришло в группу → токен и `chat_id` верные, значит дело в свойствах скрипта.
Вернулась ошибка → её текст прямо называет причину.

> **После любой правки `Code.gs`** Apps Script не подхватывает изменения сам:
> `Развернуть` → `Управление развёртываниями` → карандаш →
> `Версия: новая` → `Развернуть`. Адрес `/exec` при этом **не меняется**,
> в сайте его править не нужно.

### Выгрузка базы в Excel

В таблице: `Файл` → `Скачать` → `Microsoft Excel (.xlsx)`.
Менеджеры делают это сами, доступ к таблице выдаётся обычным способом —
кнопкой `Поделиться`.

### Если форма не отправляется

У посетителя из России `script.google.com` может не открыться. На этот
случай форма показывает запасной контакт — ссылку на ваш личный Telegram,
он задан в `FORM_CONFIG.fallback`. Заявка не теряется, человек просто
пишет напрямую.

## Цены и лиги

Цены живут в трёх местах каждой языковой страницы. Если меняете — поменяйте
во всех, иначе поисковики и ИИ будут показывать старые:

1. карточки в блоке `<div class="leagues">`;
2. ответ про стоимость в блоке `<div class="faq">`;
3. разметка `application/ld+json` в `<head>` — там поля `"price"`;
4. подпись лиги в `window.FORM_CONFIG` (выпадающий список в форме заявки);
5. `seo.prices` в `window.SCHEDULE_CONFIG` — цены в разметке `Event`.

Плюс файл `llms.txt` в корне: из него ИИ-ассистенты берут краткую сводку
о продукте.

## Расписание игр

Календарь на страницах **не хранится готовым списком** — он вычисляется от
сегодняшней даты по правилам. Поэтому он не может устареть: что бы ни
случилось, посетитель всегда видит ближайшие игры, и делать для этого ничего
не нужно.

### Сетка игр

Лежит в `schedule.js`, в массиве `RULES` в самом начале файла:

```js
{ league: 'l12', stream: 'eastern', weekday: 3, time: '19:00', tz: ET, hours: 2 },
```

| Поле | Что значит |
|---|---|
| `league` | лига: `l12`, `l24` или `l36` — от неё зависит кнопка заявки |
| `stream` | поток: `intl`, пояс (`eastern`, `central`, `mountain`, `pacific`) или штат (`ny`, `fl`, `tx`, `il`, `co`, `az`, `ca`, `wa`) |
| `weekday` | день недели: **0 — воскресенье**, 1 — понедельник … 6 — суббота |
| `time` | местное время **в поясе потока**, не по UTC |
| `tz` | часовой пояс этого города |
| `hours` | длительность: `2`, `2.5`, `4` |
| `nth` | только для ежемесячных игр: `2` — вторая такая-то неделя месяца |

Время привязано к городу, а не к UTC, специально. При переходе на летнее
время игра остаётся в те же 19:00 по местному, а сдвигается её время в
остальных поясах. Если привязать к UTC, было бы наоборот: дважды в год игра
«уезжала» бы на час для всех участников сразу.

Потоки — это открытые игры на английском:

- **International** — по лондонскому времени, для всех, кто не в США;
- **четыре часовых пояса США** — Eastern, Central, Mountain, Pacific.
  У каждой такой игры на карточке перечислены штаты пояса. Штат, который
  делится между двумя поясами, записан туда, где живёт большинство его
  жителей. Аляска и Гавайи в пояса не входят — в заметке под календарём им
  предложены игры Pacific Time;
- **отдельные штаты** — New York, Florida, Texas, Illinois, Colorado, Arizona,
  California, Washington. У Аризоны свой пояс `America/Phoenix`: там нет
  перехода на летнее время.

Сейчас в сетке 30 правил, это около 60 игр в месяц:

- Лиги 12 и 24 — по игре в неделю в международном потоке и в каждом из
  четырёх поясов;
- в каждом из восьми штатов — Лига 12 и Лига 24 раз в месяц, в разные недели;
- Лига 36 — раз в месяц, по субботам: международный поток, Eastern, Central
  и Pacific.

Названия потоков, метки над игрой («Open game · State»), списки штатов
и кнопки фильтра лежат в `SCHEDULE_CONFIG` в `index.html` — в полях
`streams`, `kinds`, `states`, `groups` и `filters`. Фильтр показывает игры
одного пояса вместе с играми его штатов: в группе Central — и Central Time,
и Texas, и Illinois.

Если добавляете новый поток в `RULES`, допишите его и в эти поля, иначе на
карточке вместо названия будет пусто.

### Как отменить игру

В каждой странице, рядом с `window.SCHEDULE_CONFIG`, есть список
`exceptions`. Формат — две строки на выбор:

```js
exceptions: [
  '2026-01-01',           // в этот день не проводится ничего
  '2026-01-08 l12 eastern' // отменена только игра Лиги 12 в поясе Eastern
]
```

Список правится в `index.html`. Даты в прошлом можно не убирать — они ни на
что не влияют.

### Что ещё настраивается на странице

В том же `window.SCHEDULE_CONFIG`:

- `clocks` — города, по которым показывается время под каждой игрой
  (сейчас Лос-Анджелес, Денвер, Чикаго, Нью-Йорк, Лондон и UTC);
- `limit` — сколько игр в списке, по умолчанию 8;
- `hour12` — 12-часовой формат («7:00 PM»);
- `leagues`, `streams`, `text` — все подписи на языке страницы;
- `seo` — название, адрес и цены для разметки `Event`.

Разметку `Event` для поисковиков собирает тот же `schedule.js` — из того же
списка игр, что видит человек. Поэтому она не может разойтись с календарём,
а статическая разметка в `<head>` устарела бы в первый же месяц. Цены в
`seo.prices` — четвёртое место, где они лежат (см. раздел «Цены и лиги»).

## Пхукет: сообщество предпринимателей

Страница `marketgame.club/phuket/` —
лендинг офлайн-сообщества по модели американских торговых палат. Игра там —
один из форматов встреч, рядом с завтраками, тренингами, лекциями и вечерними
встречами. Цель страницы — чтобы человек записался на конкретную встречу,
встал в лист ожидания или написал организаторам.

Страницы используют общие `styles.css` и `form.js`, заявки идут в ту же
таблицу и ту же Telegram-группу. Отличить их просто: в колонке «Лига» у них
приставка **PHUKET ·**, а в колонке «Мессенджер» — куда человек просит
прислать адрес встречи. С какой бы языковой страницы ни пришла заявка,
в таблицу она попадает по-русски.

### Расписание встреч

Как и на главной, оно вычисляется, а не хранится списком. Правила — в начале
`phuket/meetups.js`, в массиве `RULES`:

```js
{ id: 'workshop', format: 'workshop', weekday: 4, nth: 3, time: '18:30', hours: 2, chance: 0.6 },
```

- `weekday` — день недели (0 — воскресенье), `nth` — какая по счёту неделя
  месяца, `-1` — последняя;
- `time` — **пхукетское** время. Встречи офлайн, поэтому на странице время
  всегда пхукетское, а не по часам посетителя;
- `chance` — в какой доле месяцев правило срабатывает. Без него — каждый месяц.

Какие правила сработают в каком месяце, решает не случайность, а хеш от
месяца. Поэтому план одинаков у всех посетителей и не меняется при
перезагрузке. Выходит от 2 до 6 встреч в месяц, в среднем четыре.

**Весь план на два с половиной месяца вперёд** — откройте страницу с `?plan`
в конце адреса: `marketgame.club/phuket/?plan`.

### Отменить встречу или добавить разовую

В каждой из трёх страниц внизу есть две строки:

```js
window.MEETUPS_CONFIG.exceptions = ['2026-11-14', '2026-11-19 workshop'];
window.MEETUPS_CONFIG.extra = [
  { date: '2026-11-21', time: '10:00', format: 'talk', hours: 1.5, topic: 'Тема лекции' }
];
```

- `exceptions`: дата снимает все встречи дня, «дата + id правила» — одну.
- `extra`: разовая встреча. `format` — один из `game`, `breakfast`,
  `workshop`, `talk`, `mixer`. Тему пишите на языке этой страницы.

Правится в `phuket/index.html`.

### Цены на Пхукете

Играют две лиги, цена — с команды, оплата на встрече:

| Лига | Цена | Когда в календаре |
|---|---|---|
| Лига 12 | 1 000 ฿ | вторая суббота месяца, 14:00, 2 ч |
| Лига 24 | 3 500 ฿ | четвёртый вторник месяца, 11:00, 2,5 ч |

Если меняете цену, поправьте её в `phuket/index.html` в пяти местах:
карточка «Business game» в форматах, список в разделе об игре, ответ

в `MEETUPS_CONFIG.leagues` и числа в `MEETUPS_CONFIG.seo.prices`. Плюс строка
в `llms.txt`.

### Темы тренингов и лекций

Лежат в `MEETUPS_CONFIG.topics` каждой страницы и идут по кругу от месяца
к месяцу. Списки на обоих языках должны совпадать по длине и порядку: одна
и та же позиция — одна и та же тема, иначе на разных языках одна встреча
будет называться по-разному.

## Интерактивная модель рынка

Логика живёт в `sim.js` и одинакова для всех языков. Всё, что отличается —
валюта, суммы и подписи, — задаётся в самой странице, в блоке
`window.SIM_CONFIG` внизу файла.

Суммы пересчитаны под каждый язык одним множителем, поэтому баланс модели
везде одинаковый:

| | Русский | English |
|---|---|---|
| Средний чек | 380 ₽ | $9.50 |
| Касса на старте | 2 000 000 ₽ | $50 000 |
| Реклама по умолчанию | 150 000 ₽ | $3 750 |

Границы ползунков (`min`, `max`, `step`, `value`) стоят прямо в HTML,
в тегах `<input type="range">`. Если меняете их, поменяйте и цифры
в `SIM_CONFIG` — они должны остаться согласованными.

## Архив

Папка `_archive/` лежит в репозитории, но на сайт не попадает: GitHub Pages
не публикует папки, название которых начинается с подчёркивания.

```
_archive/ru/          русская главная и политика со своими картинками
                      (hero.jpg, format.jpg, … и русское превью og.jpg)
_archive/phuket-ru/   русская страница Phuket Business League
```

Файлы лежат ровно в том виде, в каком были на сайте, пути внутри не
менялись. Чтобы вернуть русскую версию, перенесите содержимое
`_archive/ru/` в новую папку `ru/` в корне, поправьте в страницах пути
к общим файлам (`styles.css` → `../styles.css` и т. п.), адреса `canonical`
и `og:url`, а затем добавьте на обе версии переключатель языков и теги
`hreflang`. Цены на русской пхукетской странице остались старые
(850 и 3 350 бат).
В архивной русской главной остались старые потоки (`ru`, `eu`, `us`, `vi`):
если возвращать её, её `SCHEDULE_CONFIG` нужно переписать под нынешнюю сетку.

Вьетнамская и тайская версии в архив не попали, но их можно достать из
истории репозитория: они есть в коммите `c457b62` и раньше.

## Шаг 1. Публикация на GitHub Pages

1. Загрузите все файлы в репозиторий: `Add file` → `Upload files`.
   Папки `phuket` и `apps-script` сохранятся, если перетащить их целиком.
2. Откройте `Settings` → `Pages`.
3. В блоке `Build and deployment`:
   - Source: `Deploy from a branch`
   - Branch: `main`, папка `/ (root)`
4. Нажмите `Save`.

Через одну-две минуты сайт появится по временному адресу вида
`https://ВАШ-ЛОГИН.github.io/НАЗВАНИЕ-РЕПОЗИТОРИЯ/`.

Файл `CNAME` уже лежит в репозитории, поэтому GitHub сразу попробует
переключиться на `marketgame.club`. Пока не настроен DNS, сайт по домену
открываться не будет — это нормально, переходите к шагу 2.

## Шаг 2. Подключение домена marketgame.club в Dynadot

### 2.1. Открыть настройки DNS

1. Войдите в аккаунт на dynadot.com.
2. Слева выберите `My Domains` → `Manage Domains`.
3. Отметьте галочкой `marketgame.club` и нажмите `DNS Settings` в панели
   действий сверху. Либо кликните по имени домена и откройте вкладку
   `DNS Settings`.

### 2.2. Выбрать режим

В выпадающем списке вверху выберите **`Dynadot DNS`**.

Другие варианты не подойдут:
- `Dynadot Parking` — заглушка регистратора
- `Forwarding` — редирект, домен в адресной строке заменится на github.io
- `Custom DNS` — только если вы переносите домен на сторонние серверы
  имён вроде Cloudflare

Если Dynadot уже создал записи для парковки, **удалите их** перед
добавлением своих.

### 2.3. Записи для самого домена (Domain Record)

Четыре записи типа `A` — это адреса серверов GitHub Pages:

| Тип | Значение |
|---|---|
| A | `185.199.108.153` |
| A | `185.199.109.153` |
| A | `185.199.110.153` |
| A | `185.199.111.153` |

Дополнительно можно добавить четыре записи `AAAA` для IPv6. Не обязательно,
но лишним не будет:

| Тип | Значение |
|---|---|
| AAAA | `2606:50c0:8000::153` |
| AAAA | `2606:50c0:8001::153` |
| AAAA | `2606:50c0:8002::153` |
| AAAA | `2606:50c0:8003::153` |

### 2.4. Запись для www (Subdomain Record)

В разделе `Subdomain Records`:

| Субдомен | Тип | Значение |
|---|---|---|
| `www` | CNAME | `ph001player1-lab.github.io` |

Именно так — без названия репозитория, без `https://` и без слэша в конце.

### 2.5. Сохранить

Нажмите `Save DNS` внизу страницы. Без этого записи не применятся.

## Шаг 3. Дождаться и включить HTTPS

Обновление DNS занимает от пятнадцати минут до нескольких часов,
изредка до суток.

Проверить, что записи разошлись, можно на dnschecker.org: введите
`marketgame.club`, тип записи `A`. Должны появиться те же четыре адреса
`185.199.10x.153`.

Когда домен заработает:

1. Вернитесь в `Settings` → `Pages` вашего репозитория.
2. В поле `Custom domain` должно стоять `marketgame.club`.
   Если пусто — впишите вручную и нажмите `Save`.
3. Дождитесь зелёной отметки `DNS check successful`.
4. Поставьте галочку **`Enforce HTTPS`**.

Сертификат GitHub выпускает сам и бесплатно, но не мгновенно: галочка
`Enforce HTTPS` может оставаться недоступной ещё час-полтора после того,
как DNS заработал. Если она серая — зайдите позже.

После этого сайт открывается по `https://marketgame.club`,
а `www.marketgame.club` автоматически на него перенаправляется.
